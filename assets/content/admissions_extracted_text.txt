4. Dedicated Admissions Page Specifications
4.1 Admissions Overview — /admissions
Hero: Admissions & Enrolment.
Academic year clearly displayed.
Short value proposition focused on a seamless onboarding journey.
Primary CTAs: Enrol Now, Check Eligibility, Book a Demo.
Quick overview cards linking to Enrol Now, Eligibility, Calendar, Fees and FAQ.
Keep shared contact/callback CTA at the bottom.
4.2 Enrol Now — /admissions/enrol-now
Dedicated enquiry/enrolment form.
Admission process steps.
Requirements / Required Documents block.
Clear next-step CTA after form submission.
Do not hide critical requirements inside an accordion if the source design shows them prominently.
Connect form submissions to the existing lead/CRM workflow.
4.3 Eligibility — /admissions/eligibility
Age-wise eligibility criteria.
Stage-wise / grade-wise table.
Early Years, Foundation, Preparatory and Middle School where applicable.
Include mid-session / Term 2 admission note where approved.
Any additional age policy must come from approved source content; do not invent.
4.4 Calendar — /admissions/calendar
Academic year 2026–27 / approved current session.
Term 1 and Term 2 structure.
Important academic dates, assessments, project milestones and holidays when provided.
Make calendar entries CMS-editable and downloadable if a PDF is supplied.
4.5 Fees — /admissions/fees
Dedicated fee-structure page.
Separate curriculum/stream tables where approved.
Use exact approved fee values only.
Provide downloadable/printable fee schedule when a final PDF is supplied.
Clearly explain one-time fees, quarterly tuition, annual total and payment notes where approved.
4.6 FAQ — /faq
Use the supplied Parent FAQ as the source of truth.
Admissions should link to the complete FAQ page.
Do not create contradictory admissions answers outside the approved FAQ.
5. Fee Data — Critical Content Rule
Source status: The source document explicitly says “Fees (to send)” and includes reference fee graphics. Treat those graphics as references until the final approved fee schedule is supplied/confirmed.

Do not publish unapproved or inferred fee figures.
Do not copy figures from unrelated schools used only as references.
The current live page describes the fee philosophy but requests the detailed fee schedule; this gap should be resolved through the dedicated Fees page.
When the final fee PDF/table is approved, make it CMS-manageable and keep the visible webpage table synchronized with it.
6. UI / UX Direction
Use the same global Zuvio header, navigation and footer as the approved homepage.
Use complete 4-side card borders consistently, matching the homepage UI rule.
Use clear visual hierarchy for sections, with enough whitespace and strong table readability.
Use a conversion-focused hero with a clear primary CTA.
On mobile, stack tables/cards without horizontal overflow where possible.
Forms should have clear labels, validation, success state and error state.
Keep breadcrumbs: Home → Admissions → [Current Page].
Every submenu destination must be a real route, not an anchor-only link.
